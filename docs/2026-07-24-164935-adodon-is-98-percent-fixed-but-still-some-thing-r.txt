  Root cause analysis

  Here's what's actually happening. The content timing is already frame-locked
  and identical between viewport and render — both go through
  _cache_frame_for(scene.frame_current), which deterministically maps each
  Blender frame to a cache frame. So the same cache frame shows at the same
  Blender frame in both.

  The only difference is wall-clock playback rate:

  - Render: outputs every frame → the video plays at exactly scene.render.fps
  (true intended speed).
  - Viewport: Blender's default playback sync is 'NONE' ("Play Every Frame"),
  which is compute-bound. Your 550K-vertex-per-frame update can't hit 60 fps, so
  the viewport plays in unintentional slow motion — which is why "15 feels
  good."

  So when you tune to "feels good" in a laggy viewport and then render, the
  render runs at the true speed = too fast. The two fps fields are working
  mathematically, but the viewport lag corrupts your tuning, so it feels like
  they don't work.

  The fix

  Set the viewport to frame-drop (realtime) sync on import. Then the viewport
  plays at exactly the same wall-clock speed as the render (dropping frames when
  compute-bound instead of slowing down). What you tune in the viewport is
  exactly what renders — no more "too fast."
